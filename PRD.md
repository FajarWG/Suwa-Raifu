# 1. Ringkasan Produk

Suwa Life: Nihongo Days adalah game multiplayer Roblox yang menggambarkan kehidupan siswa asing yang tinggal dan belajar bahasa Jepang di wilayah yang terinspirasi oleh Suwa, Nagano.

Pemain datang sebagai siswa baru dari luar Jepang. Mereka menjalani kehidupan sehari-hari berupa:

* Mengikuti pelajaran bahasa Jepang.
* Tinggal di asrama.
* Pergi ke sekolah dengan sepeda.
* Bekerja paruh waktu.
* Berbelanja kebutuhan sehari-hari.
* Berinteraksi dengan siswa dari berbagai negara.
* Memancing di sekitar Danau Suwa.
* Mendaki bukit dan gunung.
* Menikmati festival dan kembang api.
* Meningkatkan kemampuan bahasa Jepang.
* Mengumpulkan uang, barang, teman, dan pengalaman.

Game tidak membuat seluruh Kota Suwa secara 1:1. Dunia dibuat dalam bentuk **stylized compact world**, dengan landmark yang mudah dikenali tetapi jarak antarlokasi dipersingkat agar gameplay tetap menarik.

# 4. Strategi Nama dan Perizinan

Untuk prototype publik, gunakan nama dan desain fiktif:

* Sekolah: **Nagano International Language Academy**
* Kota: **Suwako City**
* Supermarket: nama fiktif
* Perusahaan arubaito: nama fiktif
* Asrama: desain generik

Versi resmi dapat memakai nama **NICC / Nagano International Culture College**, desain gedung, logo, dan identitas sekolah setelah mendapatkan izin tertulis dari sekolah.

NICC berada di Suwa dan alamat resminya tercantum di Toyoda 445-2. Namun penggunaan nama, logo, interior, guru, siswa, dan desain sekolah untuk produk publik tetap perlu dibicarakan dengan pihak sekolah.

Jangan menggunakan:

* Logo sekolah tanpa izin.
* Nama guru atau siswa nyata tanpa persetujuan.
* Bentuk wajah orang nyata.
* Lokasi kamar asrama secara terlalu akurat.
* Merek supermarket atau restoran tanpa izin.
* Nama dan aset resmi anime *Kimi no Na wa*.

Tateishi Park dapat dijadikan referensi pemandangan dan gameplay mendaki. Namun game sebaiknya tidak menyatakan bahwa tempat tersebut adalah lokasi resmi *Kimi no Na wa* dan tidak menyalin karakter, musik, logo, atau adegan animenya.

Roblox mewajibkan creator menghormati hak kekayaan intelektual pihak lain. Konten yang memakai IP orang lain tanpa izin dapat dihapus.

# 8. Skala Map

## Rekomendasi skala

Jangan memakai skala geografis asli.

Gunakan perkiraan:

* Bangunan penting: 70–90% ukuran realistis.
* Jarak antarlokasi: dipadatkan sekitar 1:4 sampai 1:8.
* Sekolah ke asrama: 1–2 menit berjalan.
* Sekolah ke lake park: 2–3 menit bersepeda.
* Kota ke Tateishi: melalui teleport bus atau jalur hiking terpisah.
* Satu perjalanan terpanjang: maksimal 5 menit tanpa aktivitas.

Tujuannya bukan simulasi peta yang akurat, tetapi simulasi pengalaman hidup di Suwa.

# 12. Runtime AI untuk NPC

## Tahap 1 — Tanpa LLM real-time

Gunakan:

* Branching dialogue.
* Quest condition.
* Template sentence.
* Dialogue berdasarkan Japanese Level.
* NPC schedule.
* Random response terkontrol.

Ini paling aman dan murah untuk MVP.

## Tahap 2 — AI-assisted content

AI membuat dialog di luar game, kemudian dialog ditinjau dan disimpan sebagai data statis.

Contoh format:

```json
{
  "npcId": "teacher_sakura",
  "level": "N5",
  "intent": "greeting",
  "japanese": "おはようございます。きょうもがんばりましょう。",
  "reading": "おはようございます。きょうも がんばりましょう。",
  "romaji": "Ohayou gozaimasu. Kyou mo ganbarimashou.",
  "translations": {
    "id": "Selamat pagi. Mari berusaha hari ini juga.",
    "en": "Good morning. Let's do our best today too."
  }
}
```

## Tahap 3 — LLM NPC terbatas

NPC tertentu dapat menggunakan LLM:

* Guru percakapan.
* Petugas informasi.
* Teman latihan bahasa.
* Career counselor.

Alur:

```text
Roblox Server
    ↓
Go AI Gateway
    ↓
Moderation dan rate limit
    ↓
Claude atau model lain
    ↓
Structured JSON response
    ↓
Roblox filtering
    ↓
Ditampilkan kepada pemain
```

API key tidak boleh diletakkan pada LocalScript atau dikirim kepada client. Roblox memiliki Secrets Store dan server-side HttpService untuk menghubungkan experience ke layanan luar dengan lebih aman.

## Pembatasan runtime AI

* Maksimal beberapa pesan per pemain per hari.
* Hanya NPC khusus.
* Output memakai JSON schema.
* Batas karakter.
* Timeout.
* Fallback dialogue.
* Cache pertanyaan umum.
* Filter input dan output.
* Tidak membahas informasi pribadi.
* Tidak meniru guru atau siswa nyata.
* Tidak membiarkan NPC memberi informasi darurat yang tidak diverifikasi.

# 15. Non-Functional Requirements

## Performance

* Target 30–60 FPS pada mobile kelas menengah.
* Loading pertama di bawah 15 detik pada koneksi wajar.
* Tidak memuat seluruh map sekaligus.
* Gunakan instance streaming.
* Gunakan modular building.
* Gunakan LOD untuk landmark.
* Efek kembang api dibuat sebagian besar di client.
* Batasi NPC aktif berdasarkan jarak pemain.
* Hindari aset Creator Store dengan script yang tidak diketahui.

Roblox menyarankan instance streaming untuk dunia besar dan menekankan bahwa penggunaan memori berlebihan dapat menyebabkan crash atau membuat perangkat kelas bawah tidak dapat memainkan game.

## Security

* Semua uang dan reward divalidasi server.
* Client tidak menentukan hasil pekerjaan atau memancing.
* RemoteEvent mempunyai rate limit.
* API key hanya berada di Secrets Store atau backend.
* Logging transaksi ekonomi.
* DataStore retry dan session locking.
* Jangan menyimpan percakapan sensitif secara permanen.

## Accessibility

* Furigana dapat dinyalakan atau dimatikan.
* Romaji opsional.
* Subtitle untuk audio.
* Volume kembang api terpisah.
* Reduced visual effects.
* Kontrol mobile.
* Warna indikator tidak menjadi satu-satunya sumber informasi.

# 21. Risiko Utama

## Scope terlalu besar

Mitigasi:

* Jangan membuat seluruh Suwa.
* Selesaikan satu daily loop dahulu.
* Gunakan map compact.
* Tambahkan daerah sebagai update.

## AI menghasilkan kode buruk

Mitigasi:

* Code review.
* Testing.
* Script harus modular.
* AI tidak boleh langsung publish.
* Gunakan source control.

## Visual tidak konsisten

Mitigasi:

* Satu art style.
* Satu ukuran pintu, jalan, dan prop.
* Material palette.
* AI asset harus melalui art review.

## Performance mobile

Mitigasi:

* Streaming.
* Modular assets.
* Batasi particle.
* Batasi NPC.
* Client-side VFX.
* Test sejak greybox.

## Masalah izin sekolah dan merek

Mitigasi:

* Prototype memakai nama fiktif.
* Meminta izin tertulis.
* Tidak memakai logo.
* Tidak memakai orang nyata.

## Biaya AI runtime

Mitigasi:

* MVP memakai dialog statis.
* Cache.
* Rate limit.
* Model murah untuk dialog sederhana.
* LLM hanya untuk NPC premium atau area tertentu.
* Fallback response.

## Toxic chat atau penyalahgunaan

Mitigasi:

* TextChatService.
* Report system.
* Block.
* Safe zone.
* Tidak menyediakan custom unfiltered chat.
* Moderator saat event besar.
